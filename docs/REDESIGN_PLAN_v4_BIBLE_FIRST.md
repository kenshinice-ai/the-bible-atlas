# v4 重构方案：圣经优先 · 取消数量上限 · 缩放分层

日期：2026-07-26
状态：方案（未实施）
基线：v3.1（已运行验证，13 人物 / 14 事件 / 12 地点 / 15 关系 / 3 路线）

---

## 0. 一句话诊断

v3.1 把「数据模型的复杂度」做对了（BCE、置信度、现实性、坐标精度、关系生命周期都建模了），
但把「呈现」做成了**固定容量的静态版面**：一屏塞下全部实体、一张环形图画完所有关系、
一条 5000 年轴上点满所有事件。所以数据一多就崩，而现在数据太少又显得空。

**核心矛盾不是"数量限制"这条规则，而是没有"层级"这个维度。**
一旦引入 时代 → 书卷 → 人物群 → 个人 的层级，并让 zoom 驱动层级切换，
数量上限就自然消失了——因为任何一屏永远只渲染当前层级该有的那几十个对象。

## 2. 思路重构：四条主张

### 主张 1 —— 用「层级」替代「上限」

不要限制 13 个人物，而是定义 4 个层级，每层只渲染该层的对象：

```
L0  全书          1 个节点        （圣经）
L1  时代/书卷      6–20 个节点     （族长 / 出埃及 / 王国 / 先知 / 福音书 / 使徒行传）
L2  人物群/家族    30–80 个节点    （亚伯拉罕家族 / 大卫王朝 / 十二门徒 / 保罗团队）
L3  个人          全部            （不设上限）
```

`chapters` 表已经天然是 L1。L2 需要新增一张 `character_groups`（或用图社区检测算出来后落库）。

**zoom 与层级的映射**（用户明确要的"通过 zoom in / zoom out 分辨人物关系"）：

| 缩放档 | 关系图渲染 | 地图渲染 | 时间轴渲染 |
|---|---|---|---|
| z0 | 6 个时代气泡，边=时代间人物流动 | 大区聚类气泡（美索不达米亚 / 迦南 / 埃及 / 罗马） | 时代色带 |
| z1 | 人物群节点，边=群间关系强度总和 | 城市级聚类 marker | 世纪分箱柱 |
| z2 | 重要人物（importance ≥ 4）+ 群 | 单点 marker，无标签 | 事件密度 |
| z3 | 全部人物 + 全部边 + 边标签 | 单点 marker + 名称标签 | 单事件节点 + 标签 |

同一套 `zoomLevel` 状态驱动三个视图，写进 URL，三处联动。

### 主张 2 —— API 从「一次给全部」改成「索引 + 按需」

```
GET /api/works/:slug/index?locale=      → 轻量：所有实体的 slug/name/type/importance/年代/坐标（~50 字节/条）
GET /api/works/:slug/graph?level=&focus= → 当前层级的节点+边（已聚合）
GET /api/works/:slug/events?from=&to=&chapter=&character=&limit=&cursor=
GET /api/works/:slug/locations?bbox=&zoom=&minImportance=
GET /api/entities/:kind/:id?locale=      → 单实体全文详情（抽屉打开时才拉）
```

保留 `/atlas` 作为 v3.1 兼容端点，但前端改用新端点。
索引接口对 3000 实体约 150 KB，可缓存、可全量搜索、可离线过滤。

### 主张 3 —— 关系图换引擎

当前是「SVG + 固定圆周布局」。参考基准：
**≤100 节点用 SVG，101–500 用 Canvas，>500 必须先做聚类/LOD**。

- 引擎：`d3-force`（力导向）+ Canvas 渲染 + `d3-zoom`（缩放/平移）
- 布局稳定性：家族关系用固定层级（dagre），非家族关系用力导向，混合布局
- 边标签只在 z3 且边被 hover/选中时显示（解决 B5）
- **无障碍兜底（必须）**：节点-链接图的可访问性评级是 D，必须同时提供
  "关系邻接表"（人物 A → 关系 → 人物 B → 强度）的可读列表视图作为等价替代

### 主张 4 —— 地图从「点集合」改成「叙事图层」

地图现在只是"12 个金色圆点"。圣经地图真正该有的是：

1. **迁徙轨迹**（已有 routes，但只画了 3 条直线）——加箭头、加动画进度、加沿途事件锚点
2. **时间联动**——拖时间轴，地图上的点按年代淡入/淡出（解决 B2）
3. **人物轨迹**——选中亚伯拉罕，地图画出他的 吾珥→哈兰→示剑 完整路径
4. **区域面**——迦南、埃及、亚述不是"点"，应该是带模糊边界的区域（`is_inferred` 已有字段）
5. **不确定性可视化**——`coordinate_accuracy=inferred` 的点画成虚线光晕而不是实心点

## 3. 圣经数据扩容目标（取消上限）

分三批，每批都要通过现有 SQL invariants + PostGIS 校验：

| 批次 | 人物 | 事件 | 地点 | 关系 | 书卷 | 目标 |
|---|---|---|---|---|---|---|
| 现状 | 13 | 14 | 12 | 15 | 6 | — |
| 批 1 | 60 | 120 | 45 | 100 | 12 | 验证 LOD 生效、聚类正确 |
| 批 2 | 150 | 400 | 100 | 350 | 30 | 验证性能墙、分页、虚拟列表 |
| 批 3 | 300+ | 1200+ | 200+ | 900+ | 66（全书卷） | 生产目标 |

**数据纪律（沿用 v3.1 政策，不能破）**
- 争议年代一律 `range` + 明确 `confidence`，不擅自精确化
- 推定地点 `is_inferred=true` + `coordinate_accuracy=inferred`
- 每个事件仍需 ≥1 人物 / ≥1 地点 / ≥1 来源
- 中英双语 `published` 齐全，缺一不显示
- 摘要为原创结构化描述，不存大段经文

## 4. 分阶段执行

### 阶段 0：止血（不改架构，1 天）
修 B1 B3 B6 B7 B13 + 接上死数据（chapters / chronologies / iconVariant / birthPlace）。
收益立竿见影，且不阻塞后面的重构。

### 阶段 1：地图美化（1–2 天）
深色底图 + 标记分级 + 聚类 + 时间联动（B2）+ 图例。

### 阶段 2：层级模型（2–3 天）
`character_groups` 表 + chapter 暴露到 API + `zoomLevel` 进 Explore State。

### 阶段 3：关系图重写（2–3 天）
d3-force + Canvas + zoom LOD + 邻接表兜底视图。

### 阶段 4：时间轴重写（1–2 天）
默认范围取自 `work_chronologies`、标签防碰撞、时代色带、brush 选区。

### 阶段 5：API 分层 + 数据扩容（3–5 天）
新端点 + 虚拟列表 + 全局搜索接上 `/api/search` + 批 1→批 3 扩容。
