# 欧洲美术史 Atlas 框架

状态：R1/R2/R3/R4/R5/R6 已完成本地实现与验收；R7 已完成艺术家与 canonical 人物统一及全名/爵位字段修正；R8 已完成 96 件作品的权利审计媒体、静态构建与独立站发布；当前内容 MVP 为 48 位艺术家、96 件作品。

目标 profile：`european-art-history`。目标是独立网站 / 独立静态构建，不并入圣经舆图、三国舆图或银河原力舆图的默认内容。

## 1. 产品定位

「欧洲美术史 Atlas」不是单一本书，而是一套有来源约束的历史艺术知识图谱。第一版以“艺术家—作品—流派—城市—事件—来源”为主线，让用户回答：艺术家生活和迁徙在哪里、作品何时创作和现藏在哪里、流派如何在城市与机构之间传播，以及同一时期不同地区如何并置比较。

只存原创摘要、结构化日期、作品元数据和公开来源；不存受版权保护的长篇评论或未经授权的大图。

## 2. 独立站边界

| 项目 | 设计 |
|---|---|
| profile | `european-art-history` |
| 作品模型 | 一个独立的 `works` 行，代表“欧洲美术史”策展语料集 |
| 地图层 | `real`，使用真实城市、博物馆、教堂、遗址和工作室地点 |
| 默认语言 | `zh-CN`，保留 `en` |
| 模式 | `single`；后续再考虑国家或时期对照 profile |
| 时间轴 | BCE/CE 历史时间 + 艺术史叙事顺序 |
| 首发部署 | 静态烘焙到独立 Cloudflare Pages 项目 |
| 与现有站点关系 | 复用引擎，不复用品牌、题词、默认作品或内容数据 |

## 3. MVP 内容范围

为避免无限扩张，MVP 固定 8 个时代带：

1. 古典地中海：希腊、罗马与早期基督教遗产；
2. 中世纪：拜占庭、罗马式、哥特式与修道院网络；
3. 文艺复兴：佛罗伦萨、威尼斯、罗马、北方文艺复兴；
4. 巴洛克与洛可可：罗马、巴黎、马德里、安特卫普与维也纳；
5. 新古典主义与浪漫主义：革命、学院和民族国家语境；
6. 现实主义、印象派与后印象派：巴黎及跨国艺术网络；
7. 现代主义：立体主义、表现主义、未来主义、包豪斯与先锋派；
8. 现代主义与战争至 1945 年：先锋派、流亡、摄影与抽象艺术。

战后和当代艺术、仍受版权保护的作品图像、私人收藏细节不进入当前 Foundation；当代内容后续单独评审。

## 4. 数据实体设计

现有 `events`、`locations`、`routes`、`sources`、双语翻译和层级时间轴可以复用。艺术家是“人物”语义的一种专业视图：保留 `artists` 专用表承载作品、流派与目录元数据，同时为每位有姓名的艺术家建立唯一 `characters` canonical 人物，并用 `artists.character_id` 连接；人物关系、事件参与、地点和来源统一走 `characters` 链，避免同一人出现两个互不连通的图节点。第一条 seed 前必须完成专用 schema 设计：

- `artists` / `artist_translations`：艺术家专业记录、生卒、国籍/地区、重要度；翻译表同时保留简短目录名与 `full_name`、`aliases`、`formal_titles`。没有可靠爵位/荣誉称号时 `formal_titles` 为空，不用现代地位标签冒充历史爵位；
- `artworks` / `artwork_translations`：作品、创作年代、媒介、尺寸、现藏信息、版权状态；
- `movements` / `movement_translations`：流派、时代归属、代表性城市；
- `artist_artworks`、`artwork_movements`、`artist_movements`：多对多关联；
- `institutions`，或明确以 `locations.location_type` 承载博物馆、教堂、学院、工作室；
- 现有 `events`：展览、委托、迁徙、艺术宣言、战争/赞助制度等历史节点；
- `artwork_event_links`：作品生命周期关联；作品是持续实体，事件以委托、创作、完成、展出、收藏、转移、修复等角色连接；
- `artist_event_links`、`artist_relations`：艺术家参与事件，以及师承、影响和合作关系；R7 将其镜像到 `event_characters`、`character_relations`，并保持艺术史专用关系表作为来源记录；
- `historical_place_names`：历史名称、语言、文字、有效年代和来源，与用户界面 `zh-CN/en` 分离；
- 现有 `routes`：艺术家旅行路线、作品传播路线、城市网络；
- 现有 `sources`：博物馆目录、公共领域学术书目、机构页面和地理来源。

只有 `artist_kind=person` 且具有明确姓名的行进入 canonical 人物映射；工坊、集体或匿名大师仍可留在 `artists` 专用表而不伪造个人身份。

## 5. 地图与界面

- 地图：城市、博物馆/教堂/学院、工作室、艺术家旅行与作品传播路线；
- 关系图：艺术家—流派、艺术家—艺术家、艺术家—机构；
- 时间轴：时代带、艺术家生涯、作品创作/展出、关键艺术史事件；
- 浏览器：艺术家、作品、流派、地点、事件、路线六类入口；
- 搜索：中英文艺术家、作品名、流派、城市和机构检索；
- 深链接：profile、locale、tab、时代、zoom、时间范围、实体和查询条件全部可恢复。

地图不渲染未经授权的作品大图；作品详情以文字、来源链接和权利审计缩略图为主。Commons 的 Public Domain、CC0、CC BY、CC BY-SA 可在验证后打包为本地 960px 缩略图；没有明确可再发布许可时只显示外部来源页，不渲染 `<img>`。

## 6. 首批规模建议

- 8 个时代；16 个流派；48 位艺术家/工坊；
- 96 件作品元数据；24 个城市/机构地点；
- 96 个作品生命周期事件（每件作品至少一个事件）；艺术家旅行或作品传播路线按后续独立清单扩充；
- 每个可见实体至少一条中英文 published 翻译和一条来源闭环。

扩容目标在第一批验收后再定，不继承圣经、三国或星战的内容数量承诺。

## 7. 版权、来源和真实性

- 事实可记录，评论文字必须原创或明确属于公共领域；
- 作品图片必须有来源、许可证、作者、署名和 alt text，否则只显示文字资料；
- `media_assets` 用 `media_kind`、`usage_mode`、`license_status` 分离“本地图片”“允许的远程图片”和“仅外链参考”；生产图像必须是 `bundled + verified`，并记录 `source_page_url`、`license_url`、`original_url`、抓取时间和 SHA-256；
- Google Arts & Culture 只作为研究线索或明确的外部提供方参考，不能把页面可见性推断成图片再发布许可；若未有单独可复用许可，使用 `external_link + pending`；
- 创作年代不确定时使用 `approximate` / `range`，不伪装成精确日期；
- “现藏地”与“创作地”分开建模；
- 归属有争议、工作室作品或复制品必须用 `confidence` 和来源说明；
- 跨文化影响只有在来源支持时才建立关系。

## 9. 框架阶段验收

范围、实体映射、版权边界、profile 名称、清单、schema 决策门和 Sprint 顺序均写入仓库。R7 验收增加：48/48 艺术家映射 canonical 人物，96 个生命周期事件与 43 个地点关联进入人物链，18 条关系具备双语标签/摘要，所有艺术家翻译具备完整姓名；爵位字段只录入有来源支撑的称号。R8 验收增加：96/96 作品各有一条媒体记录，其中 94 条是带 SHA-256 的本地 Commons 开放许可图像，2 条是 Braque 外部来源页；每条均有双语 published provenance、作者、署名和 alt text，静态构建包含 94 个图片文件；API、作品抽屉、中文/英文切换和 390px 布局均已验收。三个既有 profile 的静态产物与 seed 不发生变化。
