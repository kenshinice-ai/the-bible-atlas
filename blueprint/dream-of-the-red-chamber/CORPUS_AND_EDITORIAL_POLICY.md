# 《红楼梦 Atlas》语料与编辑政策

- 状态：`draft`
- 日期：`2026-08-15`
- 当前阻断：底本、数字来源、英译来源与评审人尚未冻结

## 1. 为什么必须先冻结语料

《红楼梦 Atlas》的关系阶段、互动事件和短引文都依赖具体章回与文本定位。不同版本在回目、文字、批语、标点、后四十回处理上可能不同。如果不先冻结输入，关系证据会无法复查，章回播放也会出现漂移。

## 2. 语料层级

建议至少区分：

| 层 | key 候选 | 用途 |
|---|---|---|
| 前八十回基线 | `core_80` | Phase 1 独立工程范围 |
| 后四十回续书层 | `continuation_40` | Phase 2 独立工程范围 |
| 特定刻本/整理本 | `edition_*` | 文本差异、标点、回目与版本定位 |
| 脂评/批语 | `commentary_*` | commentary evidence |
| 现代研究 | `scholarship_*` | scholarly interpretation |
| 本站编辑归纳 | `editorial_synthesis` | 可视化与摘要，必须披露 |

任何 API 返回的证据都应携带 `corpus_layer`。

## 3. 底本选择要求

冻结底本前必须记录：

- 书名、版本、整理者/出版者；
- 章回范围；
- 数字来源 URL 或本地来源；
- 获取日期；
- 权利状态；
- 是否含现代标点、校注或评语；
- 文件 checksum；
- 章回切分规则；
- 段落切分规则；
- 是否允许公开分发；
- 与其他版本的对齐方式。

“网上能读到”不等于“可打包再发布”。

## 4. 最小引用单位

候选结构：

```text
edition → chapter → passage → quote range
```

`passage` 应是稳定可审核单位，可按自然段或编辑切分段落建立。每个 passage 至少有：

- stable reference；
- chapter number；
- ordinal；
- source locator；
- original text 或合规摘要；
- checksum；
- segmentation version；
- audit status。

## 5. 互动事件判定

### 收录

- 两人或多人直接会面、对话或共同行动；
- 一方对另一方作出具有关系意义的决定；
- 赠予、照护、惩罚、传话、隐瞒、试探、婚姻安排；
- 某人缺席但成为行动明确对象；
- 死亡、离开、清退等改变关系生命周期的事件。

### 不自动收录

- 仅在同一场景出现但无可辨互动；
- 只有亲属事实，没有叙事作用；
- 编辑者凭一般印象推断的情绪；
- 无法定位到具体章回或来源的网络说法；
- 影视改编新增情节。

### 待裁决

- 梦境、判词和象征性平行；
- 叙述者概括但无具体场景；
- 同名、称谓或指代不明确；
- 版本之间关系结果不同。

## 6. 关系标签政策

关系标签分三层：

1. **事实层**：亲属、婚姻、主仆、同住、共同事件；
2. **文本解释层**：亲近、信任、冲突、依赖；
3. **研究/编辑层**：象征对照、制度意义、叙事镜像。

UI 不得把第三层伪装成第一层。

## 7. 引文政策

- 中文原作虽属古典公版文本，仍需核查所用数字整理本的标点、校注与版式权利；
- 默认只显示支持当前判断的短引文；
- 不建立全文镜像；
- 引文必须带章回、passage 和 edition；
- 不使用影视台词替代原文；
- 现代评论和论文以原创摘要为主，只做短引与标准引用；
- 所有引用遵循项目现有 `DATA_SOURCE_POLICY` 和媒体权利纪律。

## 8. 英文政策

现代英文全译本通常受版权保护，不能因为中文原作公版就直接打包。

两个阶段的英文内容均按以下优先顺序处理：

1. 本项目原创英文人物/关系摘要；
2. 明确公版或开放许可的英文资源；
3. 仅提供书目信息与外部来源链接；
4. 无合规英译时显示中文短引文 + 英文摘要，不伪造“原文翻译”。

翻译状态继续使用：

- `draft`
- `reviewed`
- `published`
- `superseded`

## 9. 前八十回与后四十回的两阶段工程

### Phase 1：前八十回

- 只生产和审核 `core_80`；
- 默认 UI 只显示 `core_80`；
- 第一阶段的完成率只以 1–80 回为分母；
- 不以计划中的后四十回结果补齐前八十回关系。

### Phase 2：后四十回

- 单独生产和审核 `continuation_40`；
- 使用独立 seed、coverage 和发布门禁；
- 用户开启后，界面持续显示版本层徽标；
- 与前八十回关系阶段分轨显示；
- 不把后四十回结果反向写成前八十回关系的必然结论。

## 10. 编辑工作流

```text
冻结底本
  → 章回/段落切分
  → 逐段互动候选
  → 人物指代归一
  → interaction event 审核
  → canonical relationship 归并
  → phase 与五维值
  → 双语摘要
  → 来源/版本/权利检查
  → 发布
```

每个影响人物身份、关系计数或关系阶段的决定必须进入 decision/evidence 记录，不能只留在聊天或 commit message。

## 11. 内容状态

| 状态 | 含义 |
|---|---|
| `candidate` | 自动或人工发现，未审 |
| `included` | 收录但未完成关系归并 |
| `reviewed` | 内容审核通过 |
| `published` | 可由公开 API 返回 |
| `disputed` | 重要分歧并列 |
| `excluded` | 明确排除并保留理由 |
| `superseded` | 被新版本替代 |
