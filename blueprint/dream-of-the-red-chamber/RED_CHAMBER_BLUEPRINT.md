# 《红楼梦 Atlas》产品与实施蓝图

- 状态：`draft`
- 日期：`2026-08-15`
- 阶段：`Phase 0 / Gate 0`
- 依据：现有 Literary Atlas v4 关系图、层级、时间轴、静态化和双语架构

## 1. 产品定义

《红楼梦 Atlas》是一款围绕《红楼梦》人物互动建立的双语文学探索产品。它把人物、关系、章回、场景、互动事件、家庭结构、权力结构和证据来源连接在同一个可播放、可筛选、可比较的关系工作区中。

产品的核心问题不是“人物在哪里”，而是：

- 谁与谁在什么时候形成关系？
- 这段关系同时包含多少情感、礼法、权力、依赖与冲突？
- 某次事件如何改变了两个人的距离？
- 一个人的处境由哪些家庭、性别、身份和资源结构共同决定？
- 从人物 A 到人物 B，最短关系路径和最有叙事意义的路径分别是什么？
- 同一关系在前八十回与后四十回中是否发生语义变化？

## 2. 产品目标

1. 让读者以人物为入口，而不是先理解复杂菜单。
2. 把关系从静态连线升级为可随章回变化的叙事对象。
3. 让关系判断可以回到章回、场景、互动事件和编辑说明。
4. 同时表达情感与制度，避免把《红楼梦》简化为爱情三角。
5. 通过焦点网络、路径比较和章回播放降低完整人物网的认知负担。
6. 复用 Atlas Core，但把首屏主舞台从地图换成关系图。
7. 为后续 100+ 人物扩展保留 LOD、分组、懒加载和静态 bake 能力。
8. 建立可审核的版本、引文、翻译和评论来源政策。

## 3. 非目标

首版不做：

- 不把大观园或北京做成伪精确现实地图；
- 不以“宅斗”“爱情测试”或人物 MBTI 作为主产品；
- 不用 AI 自动判断人物善恶或给关系打情绪分；
- 不声称解决作者、版本、脂评或后四十回归属争议；
- 不默认展示全书所有人物和所有边；
- 不收录未获许可的现代英译全文、影视剧照或商业插画；
- 不建设社交账号、用户评论、同人创作或众包编辑；
- 不在 Gate 0 阶段直接部署生产。

## 4. 受众

### 4.1 初读者

希望快速理解“这个人是谁、与谁最相关、为什么重要”。默认进入焦点人物视图，只看到 6–12 条最有解释力的关系。

### 4.2 重读者

按章回、场景、人物圈和关系维度回看细节，比较关系变化和伏笔。

### 4.3 学生与教师

使用可分享深链接、关系表、章回路径和对比模式组织课堂。

### 4.4 研究与编辑用户

核查关系标签、证据段落、版本层、编辑推断和待裁决项。

## 5. 产品支柱

### 5.1 人物焦点镜

选择人物后，中心显示本人，第一圈显示直接关系，第二圈显示关键中介。默认不显示无关边。

### 5.2 关系显微镜

选择一条关系后，展示：

- 双方身份；
- 关系类型与方向；
- 情感、权力、信任、依赖、冲突五个维度；
- 关系阶段；
- 关键互动事件；
- 章回证据；
- 版本和编辑说明。

### 5.3 章回播放器

按章回或章回段推进，关系图只显示当时已经形成且尚未结束的关系。播放不是装饰动画，而是状态变化的解释工具。

### 5.4 人物路径

回答“A 与 B 如何连接”。至少提供：

- 最短结构路径；
- 亲属路径；
- 权力路径；
- 情感/照护路径；
- 共同事件路径。

### 5.5 群体与空间

把荣国府、宁国府、大观园、薛家、史家、丫鬟网络等作为群体或场景层，不把它们伪装成现代地理点。

## 6. 信息架构

一级区域候选：

| 区域 | 默认对象 | 主要任务 |
|---|---|---|
| 人物 | character | 搜索、聚焦、人物卡、关系圈 |
| 关系 | relationship | 关系图、路径、维度、阶段 |
| 章回 | chapter / chapter band | 播放、筛选、事件密度、证据跳转 |
| 场景 | scene space | 荣宁二府与大观园的叙事空间 |
| 主题 | lens | 情、礼、权、财、照护、婚姻、主仆 |
| 资料 | source / edition | 底本、版本、引文与编辑说明 |

首屏不使用传统 Atlas 的“事件”作为默认 tab；默认 tab 为“关系”。

## 7. 首屏布局

### 桌面

```text
┌──────────────────────────────────────────────────────────────┐
│ 品牌 | 人物搜索 | 章回范围 | 主题镜片 | 中/EN | 分享         │
├───────────────┬──────────────────────────────┬───────────────┤
│ 人物/群体轨道  │         关系主舞台            │ 焦点阅读器      │
│ 约20核心+15上下文│ ego / compare / full graph │ 人物或关系详情  │
│ 筛选与书签      │                              │ 证据与阶段      │
├───────────────┴──────────────────────────────┴───────────────┤
│ 章回播放器：段落、关键事件、关系增减、当前章回说明             │
└──────────────────────────────────────────────────────────────┘
```

关系舞台占主区 55–65%；右侧阅读器约 28–34%；左侧人物轨道保持窄而高效。地图不占首屏。

### 移动端

- 顶部人物搜索；
- 中部焦点关系图；
- 底部常驻章回控制；
- 详情使用可关闭的全高 sheet；
- “图 / 关系表 / 证据”三个等价视图；
- 不在移动端默认开放完整网络。

## 8. 核心用户旅程

### 8.1 从贾宝玉开始

选择贾宝玉，默认显示林黛玉、薛宝钗、贾母、贾政、王夫人、袭人、晴雯等直接关系。切换“权力”镜片时，亲密边弱化，家长和制度边突出。

### 8.2 比较林黛玉与薛宝钗

双人物比较显示各自与贾府核心、丫鬟网络和婚姻制度的连接差异；不得将比较简化为“谁更适合宝玉”。

### 8.3 播放一段关系

打开某对人物关系，按章回查看“初识—靠近—误解—修复—断裂/终止”等阶段；每个转折可打开对应互动事件和章回证据。

### 8.4 查看王熙凤的权力网络

选择“权力/资源”镜片，观察命令、代理、经济依赖、家务管理和冲突如何围绕王熙凤分布。

### 8.5 从刘姥姥观察贾府

以外部观察者为焦点，查看阶层、资源、礼仪和互惠关系；此旅程用于防止产品只围绕宝黛钗。

## 9. 成功指标

### 内容质量

- 约 20 位核心人物均有已审核简介、群体、关键关系和章回证据；
- 约 15 位上下文人物具备支撑核心关系所需的身份和证据；
- 每条已发布关系至少有 1 个阶段和 1 条证据；
- 关系维度不得由无证据的模型推断直接发布；
- 前八十回与后四十回来源层可区分；
- 中文完整，英文只发布审核过的原创摘要或合规翻译。

### 体验质量

- 新用户 30 秒内能回答“此人与谁最相关”；
- 3 次操作内可从人物到达具体关系证据；
- 焦点图默认节点不超过 12，边不超过 20；
- 完整 100 人网络不阻塞主线程；
- 关系表可完成与图相同的选择和跳转；
- 深链接恢复人物、比较对象、章回、镜片和视图模式。

### 工程质量

- 动态 API 与静态 artifact 计数、身份和发布资格一致；
- 390×844、768×1024、1280×800、1440×900 无横向溢出；
- 所有常规文本对比度 ≥ 4.5:1；
- reduced motion 下章回切换无强制飞行动画；
- 新 profile 不改变 Bible、Three Kingdoms、Galaxy、Art、Music 现有行为。

## 10. 阶段

1. **Gate 0：规划冻结。**
2. **Phase 1：约 20 位核心人物 + 约 15 位上下文人物，完成前八十回关系工程与产品闭环。**
3. **Phase 2：保持同一人物骨架并补充必要人物，独立完成后四十回 continuation 工程。**
4. **Phase 3：扩展人物、场景图、课堂模式与高级分析。**
