# 《红楼梦 Atlas》视觉设计系统

- 状态：`draft`
- 日期：`2026-08-15`
- 设计方向：编辑型关系工作区，而非粉色爱情应用或仿古网页

## 1. 视觉主张

关键词：

- 漆、绢、胭脂、青玉、黛色；
- 克制、层次、细密、可阅读；
- 文学编辑感；
- 夜读式沉浸；
- 关系图优先；
- 不做大面积纸纹、卷轴、花瓣和古风边框。

UI UX Pro Max 的初次自动建议给出高饱和粉色“romance rose”方案。本项目明确**拒绝**该方案，因为它会把《红楼梦》缩减为爱情题材，也不适合高密度图数据。保留其“Editorial Grid”“关系图必须有列表替代”“常规文字对比度 ≥4.5:1”等建议。

## 3. 颜色使用纪律

1. 节点颜色默认表示群体，不表示性别。
2. 边颜色只在选定 lens 中表示关系语义。
3. 关系状态还要用线型、箭头、图标或文字说明。
4. `brand-deep` 只用于大面积图形、分隔线和装饰，不用于常规文本。
5. 不使用红/绿作为唯一正负编码。
6. 不用透明度单独表示可信度。
7. 选中态统一使用 `--focus` 描边，不随人物群体颜色变化。

## 4. 群体色候选

群体色用于节点填充，必须与关系边色错开：

| 群体 | 候选色 |
|---|---|

| 宁国府网络 | `#8F666E` |

群体不得超过 8 个同时使用纯色；超过后使用形状、描边和筛选。

## 5. 排版

### 字体

离线优先：

```css
--font-display:
  "Songti SC", STSong, "Noto Serif CJK SC", "Noto Serif SC",
  "Source Han Serif SC", SimSun, Georgia, serif;

--font-body:
  Inter, ui-sans-serif, system-ui, "PingFang SC",
  "Hiragino Sans GB", "Microsoft YaHei", sans-serif;
```

- 标题、人物名、短引文使用 serif；
- 控件、表格、标签和长说明使用 sans；
- 不依赖在线 Google Fonts；
- 中文 letter-spacing 默认为 0；
- 英文 title case 不强行套用到中文。

### 字号

离散 token：12 / 14 / 16 / 18 / 22 / 28 / 36px。

- 正文不低于 16px；
- 表格辅助信息可 14px；
- 12px 仅用于非关键 metadata；
- Canvas 标签视觉等效不低于 12px，并随缩放保持屏幕可读。

## 6. 形状与布局

- 4px 基础网格；
- 常规间距 8 / 12 / 16 / 24 / 32px；
- 通用圆角 6–10px；
- 不使用 18–24px 的大圆角制造 SaaS 卡片感；
- 人物节点为圆形或轻微椭圆，群体节点为圆角矩形；
- 场景节点使用房间/院落轮廓；
- selected 节点增加 3px 高对比描边和外环；
- 不能只靠节点大小表示重要性。

## 7. 关系图视觉层级

渲染顺序：

1. 群体区域或弱背景；
2. 非活跃关系；
3. 当前 lens 关系；
4. 选中路径；
5. 节点；
6. 节点标签；
7. tooltip / evidence anchor。

默认状态：

- 非焦点边 opacity 0.12–0.22；
- 焦点一跳边 0.75–0.9；
- 路径边 1.0；
- 非相关节点仍保留轮廓，避免“突然消失”；
- 边标签只在选中、键盘 focus 或显微镜模式显示。

## 8. 动效

- 常规过渡 150–240ms；
- 章回推进的布局过渡 280–450ms；
- 新节点从所属群体附近出现；
- 关系变化使用线宽/线型过渡，不使用爆炸或闪烁；
- 不使用 `back.out` overshoot 处理数据节点；
- 不使用持续花瓣、翻页、视差；
- reduced motion 下直接切换并给出文本摘要。

## 9. 背景

现有 Atlas 的多层径向渐变可在该 profile 中进一步收敛：

```css
:root[data-profile="red-chamber"] body {
  background:
    linear-gradient(180deg, rgba(221,107,116,0.035), transparent 260px),
    var(--bg);
}
```

只保留一个极弱色带，不做可感知光斑。

## 10. 图标

- 使用项目统一 SVG icon library；
- 不使用 emoji；
- 人物类别不以发型、性别化头像或影视脸谱表示；
- 关系 facet 使用抽象符号并配文字；
- icon-only button 必须 `aria-label` + tooltip；
- 触控目标最小 44×44px。

## 10.1 人物图像

- 所有正式人物使用原创虚构形象，不使用影视剧照或演员脸；
- 关系图默认显示 1:1 avatar，小尺寸下仍保留发式和轮廓辨识度；
- 人物详情优先显示 4:5 portrait；
- 全身人物卡使用 2:3 fullbody，完整展示发式、首饰、服装层次与鞋履；
- 图片不替代人物名，关系图节点始终保留文字标签或可访问名称；
- 详细生成、妆造、权利和审核规则见 [CHARACTER_VISUAL_ASSET_POLICY.md](CHARACTER_VISUAL_ASSET_POLICY.md)。

## 11. 无障碍

- 图不是唯一入口，必须有关系表；
- 颜色有线型、箭头、端点和文字冗余；
- Canvas 提供简洁 `aria-label`，具体关系由 DOM 表承载；
- focus 顺序与视觉顺序一致；
- 支持 skip link 跳过人物轨道；
- tooltip 内容也可通过 focus 触发；
- 所有抽屉关闭后 focus 回到来源节点；
- 章回变化通过克制的 live region 宣告。

## 12. 视觉验收

必须在以下内容上验证：

- 2 字、3 字、4 字人物名；
- 中英文长关系标签；
- 12 个焦点节点和 20 条边；
- 100 人筛选网络；
- 无英文翻译；
- disputed relation；
- 关系 phase 重叠；
- 390×844、768×1024、1280×800、1440×900；
- 常规、hover、focus、selected、disabled、loading、empty、error。
